# jcc-eval-slice-economy-merge

金铲铲风格自走棋 **AI Coding Agent 评测切片**：单场景备战原型，实现「经济循环 + 三连升星」两个核心机制，并以 Play Mode 状态断言完成自动化验收。

- 引擎：团结引擎 / Unity 6.6 (6000.6.4f1)，C#
- 美术资源：零外部依赖（棋子为纯数据对象，UI 为代码生成的 TextMeshPro 文本）
- 验收方式：Play Mode 中逐条状态断言（非截图/日志自述），结果落盘 `results/playmode_log.txt`

## 为什么选这个切片

经济循环与三连升星是自走棋品类的两根承重梁：前者决定节奏（收入、利息、连胜/连败博弈），后者决定成长体验（收集→合成→质变）。两者互相咬合（购买消耗金币、合成改变备战席状态），是检验状态管理与数值规则正确性的最小完备切片；同时规模可控，适合在单场景内完成全链路自动化验证。

## 功能范围

**做**
- 每回合结算经济：基础收入 5 + 利息 `min(floor(gold/10), 5)` + 连胜/连败奖励（2~3 连 +1，4 连 +2，5 连及以上 +3）
- 商店 5 槽位，刷新消耗 2 金币，余额不足时按钮禁用并输出「金币不足」提示；刷新不扣卡池
- 至少 2 种棋子（1 费 `p1_melee` / 2 费 `p2_ranger`），购买扣对应费用，余额不足拒绝且状态不变
- 备战席 8 槽；同名 1 星达 3 张立即合成 1 张 2 星（2 星放入第一张原位置）
- 2 星属性 = 1 星 × 1.8 向下取整（double 计算，规避 float 精度陷阱）
- 所有关键状态（`gold`、`interestThisRound`、`winStreak`、`lossStreak`、`shopSlots`、`bench`、`pieceId`、`star`、`baseHp`、`baseAtk`）为 public/[SerializeField]，Play Mode 中 Inspector 直读

**不做**（切片边界）
自动战斗、羁绊、装备、人口升级、卡池共享、多玩家、美术资产、动画特效、3 星合成。

## 运行方式

1. 用团结引擎 / Unity 6000.6.4f1 打开 `project/`（首次打开会重新导入依赖）
2. 打开场景 `Assets/Scenes/SampleScene.unity`
3. 点击 Play —— 场景中的 `GameBootstrap` 会在 Awake 时装配管理器与 UI；`PhaseRunner` 自动运行全部验收断言，并把结果追加写入 `<工程根>/results/playmode_log.txt`
4. 手动玩法：底部面板显示金币/利息/连胜/连败/商店/备战席；`Refresh Shop` 按钮（金币不足自动禁用）、`End Round` 按钮结算一回合；购买通过 `BenchManager.TryBuyShopSlot(int)`（验证器与后续 UI 均可调用）

## 验收结果摘要

- **阶段 1（经济循环）**：初始 50 金利息 5；49 金结算利息 4 / 50 金利息 5；1 金刷新拒收不扣费并有「金币不足」提示，2 金刷新后余额 0 且槽位仍 5；连胜 0→2 的结算增量 = 5 + 利息 + 1（实测 delta=11）；连续 5 回合无 NaN/负值
- **阶段 2（三连升星）**：3 张同名 1 星立即合成 1 张 2 星（1 星余量 0、2 星 1、金币按 3 次购买扣减）；2 星属性 = floor(101×1.8)=181 / floor(11×1.8)=19；第 4 张不误合成；跨棋子合成互不影响；Inspector 改 1 星 `baseHp` 202→200 后新合成 2 星 =360、旧 2 星保持 =363（证明非硬编码）；余额不足购买被拒且 `bench`/`gold` 不变
- **阶段 3（交叉回归）**：升星逻辑合入后 A1~E1 重跑全过；4 轮「刷新→购买→合成→再购买→结算」账本逐步核对一致（gold/1星/2星/备战席数全部吻合）；改刷新费用 2→4 后扣费与拒绝阈值联动；UI 文本与内部字段逐项一致（gold/interest/连胜/连败/备战席数/合成数/提示语/槽位数）
- **阶段 4/5**：仓库文件齐备（见下），推送后本地 HEAD 与远程 main SHA 一致、页面公开可访问

## 最终判断

**判定：机制正确（已验证），具备继续开发条件。**

依据：
1. 73 条 Play Mode 状态断言全部通过，覆盖全部验收项且断言对象为 Inspector 可见的内部状态字段，不是 UI 或日志自述；
2. 账本守恒验证（B3）表明经济与合成两条状态机在混合操作序列下不产生不一致；
3. 反硬编码验证（E2/C3）证明数值来源于 Inspector 可改配置而非写死常量；
4. 单场景装配 + 自动验收驱动（`GameBootstrap` + `PhaseRunner`）使后续切片可在同一框架下增量验证。

已知限制见下节；在补齐战斗、卡池、人口等系统前，产物定位为「机制正确的备战原型」，尚未构成完整游戏循环。

## 已知限制

- 棋子为纯数据对象（非场景 GameObject），无棋盘摆放概念；备战席只是 8 槽列表
- 商店随机填充不扣卡池，无卡池概率与等级规则
- 「本回合胜负」由 Inspector 上的 `simulateWinThisRound` 模拟，无真实战斗
- 只实现 1 星→2 星；3 张 2 星不会合成 3 星
- UI 文案为英文/数字（原型未引入中文字体资产）；「金币不足」等断言提示语存于内部字段（中文），UI 显示英文对应文案
- `p2_ranger` 配置演示了 E2 非硬编码验证后保留 `baseHp=200`（默认 202）的运行时修改仅存在于验证会话，不会写回资产
